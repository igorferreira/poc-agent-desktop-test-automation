# C5 — Erros de validação

Antes, leia `cases/AGENT.md`. Ele diz como ler a tela, como digitar e como gravar o resultado.

## Objetivo

Provocar três erros de entrada e relatar as mensagens que o sistema mostrou, na ordem. Nenhum cliente pode ser gravado.

## Pré-condição

- O operador preparou o ambiente e passou o `run_id`.
- O app está no menu principal: o identificador no canto direito da linha 1 é `T01`.
- Confira isso com uma leitura antes de qualquer outra coisa. Se não for `T01`, pare e avise o operador.

## O que fazer

1. No menu, escolha a opção `5`, que não existe, e confirme. Leia a mensagem. O app deve continuar no menu.
2. Abra a tela de inclusão de cliente.
3. Tente incluir um cliente com um código que já existe:

   | Campo | Valor |
   |---|---|
   | Código | `000001` |
   | Nome | `DUPLICADO` |
   | CPF | `44444444444` |
   | Cidade | `NITEROI` |
   | UF | `RJ` |

   Preencha os cinco campos, confirme e leia a mensagem.
4. Cancele a digitação para limpar o formulário. Leia a tela e confira que o código e a mensagem foram limpos.
5. Tente incluir um cliente com UF que não existe:

   | Campo | Valor |
   |---|---|
   | Código | `000101` |
   | Nome | `UF ERRADA` |
   | CPF | `55555555555` |
   | Cidade | `RECIFE` |
   | UF | `XX` |

   Preencha os cinco campos, confirme e leia a mensagem.
6. **Termine na tela de inclusão.** Não cancele, não volte ao menu e não tente outra inclusão.

Depois de um erro, o sistema mantém os campos preenchidos. Isso é o esperado.

## O que declarar

Em `claims` do `evidence/<run_id>/agent-result.json`, com `"case": "C5"`:

| Chave | Tipo | Formato |
|---|---|---|
| `mensagens` | lista de 3 textos | O texto da linha 24 depois de cada erro (passos 1, 3 e 5), nessa ordem, exatamente como na tela |

Formato (valores fictícios):

```json
"claims": { "mensagens": ["PRIMEIRA MENSAGEM", "SEGUNDA MENSAGEM", "TERCEIRA MENSAGEM"] }
```
